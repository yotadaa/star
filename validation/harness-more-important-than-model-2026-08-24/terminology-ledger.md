# Terminology ledger

| Term | Accepted meaning | Direct source | Rejected alternatives | Wording used in article |
|---|---|---|---|---|
| Agent harness | The system layer that organizes context, tools, state, permissions, constraints, tracing, and recovery around a base model. | [Harness-Bench abstract](https://arxiv.org/abs/2605.27922) | A synonym for the model; a prompt template alone. | “the execution system around the model” on first use, then “harness.” |
| Scaffold | A harness or agent wrapper that presents tools, manages context, and decides when execution stops. | [The Scaffold Effect](https://arxiv.org/abs/2607.22585) | Training scaffold; physical construction scaffold. | Used only when naming the paper or its evaluated wrappers. |
| Plugin in DeepSeek Harness | A Cordis-mounted component that can provide agent functions such as the model adapter, tool registry, session log, or agent loop. | [DeepSeek architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) | A browser add-on; a cosmetic marketplace package only. | “runtime component” where the generic word might mislead. |
| “Everything is a plugin” | DeepSeek's design claim that models, tools, skills, sessions, sandboxes, storage, loops, scheduling, and UI can be replaced or recomposed through its plugin system. | [DeepSeek Harness launch page](https://deepseek.com/harness/en/) | Every dependency is safe; every plugin can be mixed without compatibility work. | Quoted once, then explained through named components. |
| Cordis | The plugin framework under DeepSeek Harness; it manages mounted components, dependencies, and reversible effects. | [DeepSeek architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md); [Cordis paper](https://github.com/cordiverse/paper) | A model, benchmark, or protocol. | “the Cordis plugin runtime.” |
| Model-harness pair | One model backend evaluated inside one specified harness configuration. | [Harness-Bench](https://arxiv.org/abs/2605.27922); [The Scaffold Effect](https://arxiv.org/abs/2607.22585) | A model score that can be transferred unchanged to another harness. | “model-harness pair.” |
| Agent-computer interface (ACI) | Commands and feedback formats designed for a language-model agent's interaction with a computer. | [SWE-agent paper](https://arxiv.org/abs/2405.15793) | A human graphical interface alone. | Defined once as an earlier name for a harness-facing design problem. |
| Trace | A recorded sequence of model-visible context, tool calls and results, and related execution events. | [DeepSeek Harness launch page](https://deepseek.com/harness/en/); [Harness-Bench](https://arxiv.org/abs/2605.27922) | A faithful window into hidden model cognition in every provider. | “execution trace”; the article avoids claiming full access to private reasoning. |
| Pass@1 | The share of tasks solved on the first evaluated attempt under the study's protocol. | [Claw-SWE-Bench](https://arxiv.org/abs/2606.12344) | General product reliability outside the benchmark. | Used only beside the named benchmark and protocol boundary. |
| Tokens per solved task | Total token use divided by solved tasks for one evaluated model-harness cell. | [The Scaffold Effect](https://arxiv.org/abs/2607.22585) | Token use per run; monetary cost under every provider. | “tokens per solved task.” |
| Developer preview | An early release whose maintainers warn of rough edges and compatibility-breaking changes. | [DeepSeek repository](https://github.com/deepseek-ai/deepseek-harness); [maintainer comment](https://news.ycombinator.com/item?id=49285244) | Production-stable release. | “developer preview.” |
| Indirect prompt injection | Instructions embedded in content that an agent reads, rather than in the user's direct request, which may steer later tool use. | [A.I.G DeepSeek Harness assessment](https://arxiv.org/abs/2608.16393) | Proof that every plugin is malicious; a model-only issue with no execution consequence. | “indirect prompt injection.” |
| “More important” | More decisive for an operational choice because it changes cost, latency, failure behavior, tool access, observability, or safety even when the model remains fixed. | Synthesis of C01, C06, C07, C08, C11, and C12 in the claim ledger. | A universal claim that the base model no longer matters. | Defined explicitly in the opening section. |
