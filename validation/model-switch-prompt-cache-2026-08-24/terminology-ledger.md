# Terminology Ledger

| Term | Operational definition in this article | Evidence | Guardrail |
|---|---|---|---|
| conversation | Claude Code's retained sequence of user messages, model responses, and tool results. | [Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code), [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching) | Conversation continuity does not imply cache continuity. |
| context | The full request Claude Code sends: system prompt, project context, conversation history, tool results, and the newest message. | [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching) | Avoid using “memory” as a synonym. |
| prefix | The identical beginning of a request that the cache can match. | [Claude Platform prompt-caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | Matching is exact up to the cache breakpoint. |
| prefill | The input-processing phase in which the model reads the request and builds attention state before producing output. | [Maximizing Claude Code sessions](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions), [Prompt Cache paper](https://arxiv.org/abs/2311.04934) | Do not equate prefill with output generation. |
| prompt cache | Server-side reuse of a previously processed request prefix. | [Claude Platform prompt-caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) | This article discusses Anthropic's documented implementation, not every provider's cache. |
| cache hit / read | Reuse of a stored prefix, billed by Anthropic at 0.1 times base input price. | [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) | Applies while an eligible entry remains warm. |
| cache write / creation | Tokens processed and stored as a new cache entry; the current multipliers are 1.25 times base input for a five-minute entry and 2 times for a one-hour entry. | [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) | A switch turn can contain cache creation plus new input and output. |
| warm cache | A matching cache entry that remains within its TTL and is refreshed by reuse. | [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching) | A cold or expired cache changes the opportunity cost of switching. |
| model switch | A `/model` change that preserves the conversation but selects a different model-specific cache. | [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching), [Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code) | It is not a context clear. |
| effort switch | A `/effort` change within a model; effort is part of the cache key and a change causes the next request to read the history without cache hits. | [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching) | The same cache warning applies even without changing model family. |
| break-even turn | The first cheaper-model request count at which its initial cache rebuild plus later reads no longer exceeds the warm expensive-model prefix cost under stated assumptions. | Derived from first-party prices in `claim-ledger.md` | This is a prefix-only comparison, not a full task-cost prediction. |
| semantic continuity | The new model receives the retained conversation and can use it as input. | [Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code) | It says nothing about cached compute or identical behavior. |
| computational continuity | The next request can reuse already-computed prefix state. | [Claude Code caching docs](https://code.claude.com/docs/en/prompt-caching) | A model or effort switch breaks this continuity. |
